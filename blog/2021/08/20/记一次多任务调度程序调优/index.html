Redis 多线程

记一次多任务调度程序调优

Posted by jamie Blog on 2021-08-20 · 阅读 -- 次

1. 背景

1.1 原始方案与存在的问题

  1. 循环遍历企业，按照企业抓拍。排在前的企业抓拍会阻塞排在后面的企业，严重影响用户体验。
  2. 采用定时任务执行，周期过短，单个周期内不能执行完数据抓拍；周期过长，抓拍延迟严重。
  3. 单线程执行，抓拍严重串行化，效率低，不能充分利用服务器资源。

3. 碰到的问题与解决方案

3.1 线程池拒绝策略

3.1.1 描述与分析

在线程池没有空闲线程的情况下，有新的任务需要执行，默认线程池拒绝策略为抛出异常。由于没有多余的线程可以使用，程序没有做任何补救措施。

当后续线程池有空闲线程的时候，sn轮询线程已经轮询到的sn也是不定的，所以应该执行某个小票队列中的数据也变得随机，最坏的情况就是，某一个小票队列一直没有被执行到。

3.1.2 解决方案

修改线程池拒绝策略为：CallerRunsPolicy，由调用者线程执行。
如此一来，sn轮询线程就会变成抓拍线程，并执行抓拍任务。

这样就保证了，小票队列的执行顺序与sn对列轮询顺序一致。

3.1.3 方案缺陷

若在sn轮询线程执行抓拍过程中，有了空闲线程，该空闲线程就被闲置，只能等到sn轮询线程将本次抓拍执行完成后继续轮询sn队列，并将下一个 sn 任务交由该闲置线程处理，该线程才能被利用。

由于目前很多时候，都是小票抓拍时间未到，这将导致抓拍线程执行任务特别快，闲置线程不会闲置太久。就算要执行抓拍，抓拍时间也在4到5秒能执行完成，该闲置线程也只能闲置4到5秒的时间，还算能接受。

3.2 sn 队列 score 设置不合理，导致sn线程不能轮询

3.2.1 描述与分析

改问题现象：sn 线程不能继续轮询下去，一直卡在某一个特定的 sn。

轮询实现方案： 基于score分数来进行轮询，当轮询到某个sn时，从队列中取出两条数据，cur 和 next ，并记录下一次查询时的起始分数 = next 的 score。
下一次取数的时候，就能跳过上一步骤的 cur ，从而达到轮询下一个数据的目的。

倘若 有多条数据，score 分数相同。

3.2.2 解决方案

sn 数据入队列的时候，score设置为当前时间+三位随机小数（降低重复率）

3.3 sn 队列 score 设置不合理，队列数据排序被重置

3.3.1 描述与分析

程序中，某一小票队列中的优先级最高的数据执行抓拍。并且该条数据执行抓拍任务时，由于某些原因，导致重试。则需要重新加入该小票队列。此时也会重新添加sn队列。该sn的score为当前时间，排到了队列尾部。在极端情况下，多个小票数据存在此种情况，sn队列中的数据大多都被重置。这将影响到 sn 轮询线程的轮询逻辑（由于轮询依赖 score ）。

下一次轮询的时候，由于nextScore=1626658800178,基于此条件，则查询出来的数据为如下两条，正常情况下，cur应该指向最后一条数据，然而当前现象是next指向了这一条。导致被重置的数据没有执行。极端情况下，该现象会成倍扩大，执行顺序会被打乱。

3.3.3 解决方案

sn 入队列的时候，同步判断该数据是否存在，不存在则添加，存在则不做处理。

3.4 线程池线程无法复用

3.4.1 描述与分析

3.5 httpClinet使用不当，导致资源不能及时释放

3.5.1 描述与分析
1

CloseableHttpClient httpClient = HttpClients.createDefault();

未使用线程池管理，每次执行抓拍时，手动创建默认的httpClinet，没有手动关闭流，资源不能及时释放。高并发下，将导致内存大量被占用，最后程序不能申请足够的内存，从而导致宕机。

3.5.2 解决方案
  1. 程序启动初始化httpclient，后续直接使用。
  2. 手动及时关闭流。

3.7.2 解决方案
  1. 若 sn 队列没有数据时，sn 轮询线程依然会进行 redis 访问，给 redis 带来非必要的压力，浪费资源。
  2. 小票抓拍线程，在未获取到分布式锁的情况下（有其他线程在执行该设备下的小票抓拍）， 会释放线程，短时间内可能存在大量的线程执行任务。为了尽可能降低并发访问量，需设置休眠时间。

在相应位置，设置休眠时间，有效降低 redis 的请求量。

    /**
     * 基于Netty框架的事件驱动的通信层，其方法调用是异步的。
     * Lettuce的API是线程安全的，所以可以操作单个Lettuce连接来完成各种操作
     *
     * @param redisProperties
     * @return
     */
    public static LettuceConnectionFactory buildLettuceConnectionFactory(RedisProperties redisProperties) {
        LettuceClientConfiguration lettuceClientConfiguration;
        if (null != redisProperties.getLettuce().getPool()) {
            LettucePoolingClientConfiguration.LettucePoolingClientConfigurationBuilder lettucePoolingClientConfigurationBuilder = LettucePoolingClientConfiguration.builder();
            lettucePoolingClientConfigurationBuilder.commandTimeout(redisProperties.getTimeout() == null ? DEFAULT_REDIS_CONNECT_TIMEOUT : redisProperties.getTimeout());
            lettucePoolingClientConfigurationBuilder.shutdownTimeout(redisProperties.getLettuce().getShutdownTimeout() == null ? DEFAULT_REDIS_SHUTDOWN_TIMEOUT : redisProperties.getLettuce().getShutdownTimeout());

            GenericObjectPoolConfig poolConfig = buildGenericObjectPoolConfig(redisProperties);
            lettucePoolingClientConfigurationBuilder.poolConfig(poolConfig);
            //关闭延迟测量
            lettucePoolingClientConfigurationBuilder.clientResources(DefaultClientResources.builder().commandLatencyCollectorOptions(DefaultCommandLatencyCollectorOptions.disabled()).build());

            lettuceClientConfiguration = lettucePoolingClientConfigurationBuilder.build();
        } else {
            LettuceClientConfiguration.LettuceClientConfigurationBuilder lettuceClientConfigurationBuilder = LettuceClientConfiguration.builder();
            lettuceClientConfigurationBuilder.commandTimeout(redisProperties.getTimeout() == null ? DEFAULT_REDIS_CONNECT_TIMEOUT : redisProperties.getTimeout());
            lettuceClientConfigurationBuilder.shutdownTimeout(redisProperties.getLettuce().getShutdownTimeout() == null ? DEFAULT_REDIS_SHUTDOWN_TIMEOUT : redisProperties.getLettuce().getShutdownTimeout());

            //关闭延迟测量
            lettuceClientConfigurationBuilder.clientResources(DefaultClientResources.builder().commandLatencyCollectorOptions(DefaultCommandLatencyCollectorOptions.disabled()).build());

            lettuceClientConfiguration = lettuceClientConfigurationBuilder.build();
        }

        RedisStandaloneConfiguration redisStandaloneConfiguration = buildRedisStandaloneConfiguration(redisProperties);
        LettuceConnectionFactory factory = buildLettuceConnectionFactory(redisProperties, lettuceClientConfiguration, redisStandaloneConfiguration);
        factory.afterPropertiesSet();

        return factory;
    }
