索引跳跃

Posted by jamie Blog on 2023-07-05 · 阅读 -- 次

1. 前言

不知大家有没有听说过索引跳跃？

2. 最左前缀原则

我们都知道在innoDB引擎中，索引是通过B+树来实现的。如有一张user表，有三个字段，id（主键），age（年龄），name（姓名）。那么他的主键索引构建如下图。

若此时创建一个联合索引（age,name）则索引结构如下

只有当age相同时，那么才是有序的。若此时查询sql为

select id from user where age = 10 and name = '张三'；

此时会用到该联合索引，并且 age，name都会匹配得到。

那么若是 select id from user where name = '张三'呢？

由于不符合最左前缀原则，该聚合索引将不会生效。我想这一点应该是大家的共识。

3. 索引跳跃

以上结论在MySQL 8.0.13版本之前是没有任何疑问的，但是在8.0.13版本中MySQL做了相关的优化。select id from user where name = ‘张三’这条sql会使用到覆盖索引。那么它是如何进行优化的呢。

由于示例数据中，age只有10,11两个数据，所以区分度很高，在执行sql时，会将select id from user where name = '张三'优化为

1
2
3

select id from user where age=10 name = '张三'
union all
select id from user where age=11 name = '张三'

这样自然而然的就能使用到该联合索引了。这种优化机制被称为索引跳跃扫描。

当然这种机制也是存在一定的限制条件。

  1. 比如以上示例，若是age字段的值分布很广，区分度很低的情况，那么在执行sql时，MySQL可能就不会进行优化了，这个在MySQL优化器中有它自己的判断标准。
  2. 查询必须只能 依赖 一张表，不能多表JOIN。
  3. 查询中不能使用 GROUP BY 或 DISTINCT 语句。
  4. 查询的字段必须是索引中的列。
