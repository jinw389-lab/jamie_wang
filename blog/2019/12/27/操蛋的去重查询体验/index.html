操蛋的去重查询体验

Posted by jamie Blog on 2019-12-27 · 阅读 -- 次

1.前言

昨天项目上反馈一个问题，由于目前的产品无法支持，所以要稍微改进一下，现在我大概的描述一下，rating_data数据表中是保存了每次用户评分的请求记录。一个用户会进行多次评分。项目上要查询每个用户的最新评分记录。现在想想也貌似没啥，挺简单的。

2.mysql实现

由于公司用的是mysql5.7，那么针对group by的方式就没法考虑了。我想到了使用left join来实现。

由于涉及到公司隐私，我这里简化一下： 简化后的表rating_request结构,去掉了大量业务代码，为了不显的少，也保留了一些字段，但是无非就是关注在legal_person_id_card，gmt_create这两个字段上面。

CREATE TABLE `rating_request` (
  `id` bigint(20) NOT NULL COMMENT 'ID(非自增)',
  `legal_person_id_card` varchar(50) DEFAULT NULL COMMENT '法人身份证号码',
  `legal_person` varchar(50) DEFAULT NULL COMMENT '法人名称',
  `cell_phone_num` varchar(50) DEFAULT NULL COMMENT '手机号码',
  `reg_number` varchar(50) DEFAULT NULL COMMENT '注册号',
  `credit_code` varchar(50) DEFAULT NULL COMMENT '统一社会信用代码',
  `company_name` varchar(100) DEFAULT NULL COMMENT '公司名称',
  `gmt_create` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
  PRIMARY KEY (`id`),
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='评级请求记录';

一口气写完了，执行一次，看着没啥问题，就直接拷贝到项目上，改吧改吧，用上了，然后接口测试。 我艹，吓了我一跳，竟然还有重复数据，于是我认真看了一下我在mysql中的执行记录。
哎！数据问题，原来表中的时间最小精度是秒。所以如果在同一秒的时间请求两次，那么这两条记录时间就是相同的。这可咋整呢。我必须在取其中一条。思来想去也没找到合适的办法，想过借助其他的字段查询，发现也走不通，还是必须在这个时间上下手；我这个时候就开始心里操蛋当时做这块的那个同事，为啥不用timestamp或者时间戳，这样时间精读就够用了啊，心里一百只草泥马奔腾而过。
这没法搞啊。
no，这个问题我肯定能解决
既然这上面不能改，那么就想其他的法子呗。

抱着提高时间精读的想法，我就想怎么提高一个时间精读高的字段呢？没有啥选择，只能在gmt_date字段上做函数计算，提高精读。也就是加上毫秒值。 为了方便观察测试问题，我加上了身份证过滤条件legal_person_id_card = ‘89’

这是没有加去重逻辑的查询结果

SELECT t1.id, t1.legal_person_id_card, t1.gmt_create, t1.new_gmt_create
FROM (
	SELECT t.*, date_add(t.gmt_create, INTERVAL RAND() * 1000 MICROSECOND) AS new_gmt_create
	FROM rating_request t
	ORDER BY t.gmt_create ASC
) t1
	LEFT JOIN (
		SELECT t.*, date_add(t.gmt_create, INTERVAL RAND() * 1000 MICROSECOND) AS new_gmt_create
		FROM rating_request t
		ORDER BY t.gmt_create ASC
	) t2
	ON t1.legal_person_id_card = t2.legal_person_id_card
		AND t1.new_gmt_create < t2.new_gmt_create
WHERE t2.id IS NULL AND t1.legal_person_id_card = '89'

执行完，竟然没有记录，在执行一次，查到一条记录。我蒙蔽了，一下子点了好多次，结果就是有时一条记录，有时没有记录
什么鬼？不过我并没多慌，我无非就是生成了一个毫秒随机时间啊，
于是我分析这块问题 date_add(t.gmt_create,interval RAND()*1000 MICROSECOND)。由于我这个会用到两次，同一条记录查询出来的结果保证不了是一样的时间啊
所以我们不能用RAND，那么我必须考虑到借用其他字读读取值了，因为只有查找当前记录中的字段数据，才能保证每次查询都是相同的。 有那个字段可以借助呢，可以考虑id嘛，数值类型，所以我就统一截取id的后4位。这里多少位无关紧要。

SELECT t1.id, t1.legal_person_id_card, t1.gmt_create, t1.new_gmt_create
FROM (
	SELECT t.*, date_add(t.gmt_create, INTERVAL RIGHT(id, 4) MICROSECOND) AS new_gmt_create
	FROM rating_request t
	ORDER BY t.gmt_create ASC
) t1
	LEFT JOIN (
		SELECT t.*, date_add(t.gmt_create, INTERVAL RIGHT(id, 4) MICROSECOND) AS new_gmt_create
		FROM rating_request t
		ORDER BY t.gmt_create ASC
	) t2
	ON t1.legal_person_id_card = t2.legal_person_id_card
		AND t1.new_gmt_create < t2.new_gmt_create
WHERE t2.id IS NULL AND t1.legal_person_id_card = '89'

执行完，终于能得到稳定的预期数据了。

3.oracle解决方案

由于公司项目要兼容mysql和oracle，所以oracle也要保证， 下面是new_gmt_create计算的实现,我这里用的是行号ROWNUM

1

cast( gmt_create AS timestamp ) + NUMTODSINTERVAL( ROWNUM / 1000, 'second' ) AS new_gmt_create
