JAVA如何回收堆外内存

Posted by jamie Blog on 2020-04-20 · 阅读 -- 次

1. 闲聊一刻

这段时间暂时没有发现啥整理的，这个月又到下旬了，时间过得非常快啊！一下子，2020年就过去了一小半年，最近想到一个问题。因为我们说道java中的内存回收机制，都是针对堆内存进行说的，那么堆外内存怎么进行垃圾回收呢，毕竟在java8以及之后的版本中，方法区内换成了元空间，元空间并不在jvm内存中，而是在我们的本地直接内存中。那么问题就来了，java中的垃圾回收机制仅仅只能管理到jvm之内的内存，那么jvm之外，我们的直接内存就不进行回收了吗，这显然是不合理的。元空间中的数据还是要进行回收。这之前，我一直都没有意识到这个问题，也没有往这方面去想过。这可是真的是触碰到了我的知识盲区。

2. 科普一下，什么是堆外内存

JVM启动的时候，需要分配一些内存，这块内存就叫堆内存，那么与这块内存相对应的就叫做堆外内存，在java8中元空间就在堆外内存中，由于堆外内存已经不是JVM的管辖范围，那么这块内存就不会进行GC垃圾回收。

3. 堆外内存的申请与释放

JDK的ByteBuffer类提供了一个接口allocateDirect(int capacity)进行堆外内存的申请，底层通过unsafe.allocateMemory(size)实现。这块内存需要手动释放，jvm不会进行回收，Unsafe类提供了freeMemory接口进行堆外内存的释放。

java每次都要手动释放这些内存，显然是不合理的，在jdk中有一个DirectByteBuffer类来表示堆外内存，并且每次DirectByteBuffer实例被创建的时候，都要创建一个Cleaner对象，这个对象会执行unsafe.freeMemory(address)，从而释放堆外内存。

下面画一张简图


Cleaner对象在创建的时候，会被加入到cleaner链中，这个first对象是cleaner的一个静态变量，和cleaner存在引用关系。RefrenceQueue是一个被用来存放需要回收的cleaner对象的队列，每次有需要回收的cleaner对象要进行回收，都会将其加入该队列中。

如果在一次GC垃圾回收的过程中DirectByteBuffer被进行了回收，那么cleaner就只有他保存了堆外内存的地址了，在下一次Full GC垃圾回收的时候，就会将cleaner对象加入到RefrenceQueue队列中，并触发垃圾回收方法，进行堆外内存的回收。在进行垃圾回收的时候，主要是做了两个事情，其一是对堆外内存的回收，其二是删除自身的cleaner的引用链表，这样的话，在下一次垃圾回收的时候，cleaner对象就会被回收了。
