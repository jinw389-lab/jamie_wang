1. 前言

我们不管在平时的工作开发中，还是阅读源码的时候，debug总是少不了的。但是要把debug用好，也要讲究一些技巧，这样我们工作效率就会大大提高。

3. 条件断点

对比条件断点，这个就用的比较多了，特别是在我们进行功能开发的时候，我们只想在某一个特定的条件下，才停住。下面来演示一下。

例如有如下代码，我想在i==5这个条件的时候被断点拦截停住。

1
2
3

for (int i = 0; i < 10; i++) {
    System.out.println(i);
}



然后debug运行代码，断点只能在满足条件的时候才能被停住。

在截图中的左下角可以看到方法的调用链路（倒序），此时我的代码断点正method1方法，如果我想回退到上一个方法。那么就在列表中选择method1，然后点击下图指示按钮，drop frames

断点已经回退上上一个方法断点中，i的值也变成了之前值。（注意：在引用对象，回调到之前的方法，想改变之前的属性值是改变不了的）。

    public static void main(String[] args) {
        new Thread(()->{
            System.out.println("线程1-1");
            System.out.println("线程1-2");
            System.out.println("线程1-3");
        },"线程1").start();

        new Thread(()->{
            System.out.println("线程2-1");
            System.out.println("线程2-2");
            System.out.println("线程2-3");
        },"线程2").start();
        System.out.println("主线程");
    }

以上代码我们直接执行多次，每次打印的结果可能都不太一样。
