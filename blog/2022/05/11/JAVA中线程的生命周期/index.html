JAVA中线程的生命周期

Posted by jamie Blog on 2022-05-11 · 阅读 -- 次

1. 前言

我好像很少写关于多线程相关的东西，也有过几篇，但是不多。但这不代表我工作中有关多线程的地方用得不多。特别是线程池相关，其实用的地方也不少。只是若在简单编写业务代码，就实现一个简单的功能，数据量也不大，用户也不多，QPS也不高的系统中，多线程用得的确并不是很多。但是做为一个多年的JAVA开发人员，多线程肯定是必不可少的。既然说到多线程，就离不开说到线程。

2. 线程的生命周期

那么我们先来聊一下线程的生命周期。这个只要从事过开发相关工作的同学，或多或少都能聊个几点。

我们直接上代码，找到Thread类中的State枚举。

    public static enum State {

我们看到线程的状态只有NEW,RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED。6个状态。

下面分别来简单描述一下这几种状态

2.1 NEW

在新建了线程，没有调用start方法之前，线程的状态就是NEW状态。当然调用了start方法，也并不意味着线程从start状态转变为RUNNABLE了，在调用了start后，线程并不会立即获得CPU的执行时间片，中间还需要很多操作系统内部的复杂逻辑操作。

2.2 RUNNABLE

当调用了Thread实例的start()方法后，下一步如果线程获取CPU时间片开始执行，JVM将异步调用线程的run()方法执行其业务代码。那么在run()方法被异步调用之前，JVM做了哪些事情呢？JVM的幕后工作和操作系统的线程调度有关。Java中的线程管理是通过JNI本地调用的方式委托操作系统的线程管理API完成的。当Java线程的Thread实例的start()方法被调用后，操作系统中的对应线程进入的并不是运行状态，而是就绪状态，而Java线程并没有这个就绪状态。操作系统中线程的就绪状态是什么状态的呢？下面画一个简图。

当操作系统中线程处于就绪状态后，就只需要等着该线程分到CPU时间片了。分到时间片，线程状态从就绪变为运行状态。在Java中，并没有定义就绪和运行两个状态，统一定义的是RUNNABLE状态。关于为何这样设计定义，后面谈，这里先放一放。

线程在执行的过程中，有可能时间片会被分配到其他线程，这个时间，该线程就失去了执行权，状态就从运行状态改为就绪状态。就这样反复执行。

2.3. TERMINATED

run方法中的代码执行完或者抛出异常，并且业务代码中没有对其进行捕获处理，线程就会变为终止状态。

2.4. TIMED_WAITING

线程处于一种特殊的等待状态，准确地说，线程处于限时等待状 态。能让线程处于限时等待状态的操作大致有以下几种：

（1）Thread.sleep(int n)：使得当前线程进入限时等待状态，等待时间为n毫秒。
（2）Object.wait()：带时限的抢占对象的monitor锁。
（3）Thread.join()：带时限的线程合并。
（4）LockSupport.parkNanos()：让线程等待，时间以纳秒为单位。
（5）LockSupport.parkUntil()：让线程等待，时间可以灵活设置。

2.5. WAITING

跟上面的状态对应，没有设置时间，线程则会处于长时间等待状态，直到其他线程将其唤醒。

2.6. BLOCKED

线程被阻塞，主要是在多线程抢占锁的过程中和读取网络IO，磁盘IO等操作。线程没有获取到锁和等待IO，那么该线程将被阻塞挂起。阻塞状态并不会消耗CPU资源。

3. 为什么JAVA中线程没有RUNNING

下面来聊聊为啥JAVA线程中没有运行状态和就绪状态呢？

对于现在的分时操作系统来说，在单CPU情况下，所有的线程其实都是串行执行的。但是为了让我们看起来像是在并发执行，人们把CPU的执行分成很多个小的时间片。

哪个进程得到时间片，那个线程就执行，时间片到了之后，就要释放出CPU，再重新进行争抢时间片。

只要把时间片划分的足够细，那么多个程序虽然在不断的串行执行，但是看起来也像是在同时执行一样。

那么，CPU的时间片其实是很短的，一般也就是10-20毫秒左右。 那么，也就是说，在一秒钟之内，同一个线程可能一部分时间处于READY状态、一部分时间处于RUNNING状态。

那么如果，明确的给线程定义出RUNNING状态的话，有一个很大的问题，就是这个状态其实是不准的。因为当我们看到线程是RUNNING状态的时候，很有可能他已经丢失了CPU时间片了。对于线程的状态，我们只需要知道，他当前有没有在正在参与执行就行了，何为参与执行？就是他的状态是可执行的，只要获得时间片，就能立即执行。那这不就是RUNNABLE吗？所以，Java就没有给线程定义RUNNING状态，而是定义了一个RUNNABLE状态。

4. 总结

该篇文章从线程的生命周期说起，谈到线程的每个状态，和之间的转换流转，并对各个状态进行了详细的描述； 最后解释了一下为什么在java中线程没有定义运行状态。
