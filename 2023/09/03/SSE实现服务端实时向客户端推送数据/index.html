SSE实现服务端实时向客户端推送数据

Posted by jamie Blog on 2023-09-03 · 阅读 -- 次

1. 前言

我想大部分后端都有过这样一个需求，就是后端如何向前端实时提供数据呢？大部分同学很快都会想到以下两种解决方案

  1. webSocket
  2. 前端轮询调用后端接口

这两种方式都可以实现，但是都有他们的弊端。

比如webSocket是一种全双工协议通道，前端可以向后端发送数据，后端也可以向前端发送数据。但是在前端无需向后端发送数据的情况下，这种方式变得相对比较重量级。第二种方式呢，开发简单，但是轮询间隔要多少时间呢？间隔时间过长，延迟就比较高，过短呢，就会发送很多次无效请求。

那么有没有更简单直接有效的方式来实现后端实时向前端推送数据呢？当然有，今天就介绍一种既开发简单又可以实时推送数据的方式，叫SSE。

2. 什么是SSE？

SSE全称叫Server-Sent Events，是一种基于HTTP协议的服务器推送技术，它允许服务器实时向客户端发送事件流（Event Stream）。SSE主要用于在浏览器和服务器之间建立持久性的单向连接，使服务器能够将实时数据或事件推送到客户端，而无需客户端明确发起请求。

2.1 SSE的优势

简单易用： 相比于其他实时通信技术（如 WebSocket），SSE更加简单易用。它使用基于 HTTP 的长轮询机制，允许服务器主动推送数据到客户端，而无需客户端发起请求。

原生支持： SSE在现代浏览器中得到了广泛的支持，无需额外的插件或依赖库。只要浏览器支持 SSE，就可以通过原生的 JavaScript API 进行开发。

兼容性： SSE是基于HTTP的标准协议，可以在现代浏览器中直接使用，无需额外的插件或扩展。

单向通信： SSE是一种服务器向客户端的单向通信方式。服务器可以实时向客户端发送数据更新，而客户端只需监听事件流，不需要自己给服务器发送请求。

实时性： SSE具备较低的延迟和较高的实时性，可以实现快速的数据推送和更新。因此，对于实时性要求较高的应用场景，如即时聊天、实时数据展示等，SSE 是一个不错的选择。

对网络和服务器的负载较低： 相比于轮询方式，SSE 通过长轮询机制减少了无效请求的数量，减轻了网络和服务器的负载。

2.2 SSE的工作原理

  1. 客户端通过普通的HTTP GET请求与服务器建立连接，请求头中包含Accept: text/event-stream，表示希望接收事件流。

  2. 服务器通过HTTP响应返回一个MIME类型为text/event-stream的响应体，并设置Content-Type为text/event-stream，表示服务器将发送事件流给客户端。

  3. 服务器在响应体中按照一定的格式发送事件数据，每个事件由一个或多个字段组成，包括事件的标识符、事件类型、数据等。

  4. 客户端使用EventSource API来监听服务器发送的事件，一旦收到新的事件，就会触发相应的回调函数进行处理。

SSE在实时数据推送、聊天应用、通知提醒等场景中具有广泛的应用。然而，需要注意的是，SSE是一种单向通信机制，只能由服务器向客户端发送事件，客户端无法直接向服务器发送消息。如果需要实现双向通信，则需要考虑使用WebSocket等其他协议。

@RestController
@RequestMapping("/v1/sse")
@Slf4j
public class SseController {

    @GetMapping("/getMsg")
    @CrossOrigin
    public SseEmitter items(){
        SseEmitter emitter = new SseEmitter();
        // 异步发送消息。每间隔1s发送1条，总共发送10条
        CompletableFuture.runAsync(()->{
            try {
                for (int i = 0; i < 10; i++) {
                    String msg = DateUtils.format(new Date(),DateUtils.DATE_TIME_PATTERN) + " 消息:"+i;
                    emitter.send(SseEmitter.event().data(msg));
                    log.info("发送消息：{}",msg);
                    Thread.sleep(1000);
                }
            } catch (Exception e) {
                e.printStackTrace();
            }
            emitter.complete();
        });
        return emitter;
    }
}

在springMVC中提供了SseEmitter类来快速实现服务端SSE，这里我们可以直接拿来使用。

</head>

<div id="sse-data"></div>
    <script>
        function sse(){
            const sseDataElement = document.getElementById('sse-data');

                //转数据为json字符串
            var jsondata=JSON.stringify(data)

            //创建sse对象，请求地址，参数，请求方法
            source = new SSE("http://localhost:8909/v1/sse/getMsg");

            //与后台连接成功触发的监听
            source.addEventListener('open', function(e) {
                console.log("open")
                console.log('连接成功');
            });

            //接收到后台数据触发监听方法
            source.addEventListener('message', function (event) {
                console.log('收到数据', event.data);
                sseDataElement.innerHTML += '收到消息时间：'+new Date() +`<br>收到消息: ${event.data}<hr>`;
            });

            //请求出错触发的监听方法
            source.addEventListener('error', function(e) {
                console.error('请求出错：', e);
            });

            //数据传输完成关闭连接触发的监听方法
            source.addEventListener('close', function(e) {
                console.log('连接关闭');
            });

            //调用发起请求
            source.stream();
        }
    </script>
</body>
</html>

启动应用，打开页面可以看到页面实时刷新数据。
