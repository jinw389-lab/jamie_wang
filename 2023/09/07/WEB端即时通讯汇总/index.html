WEB端即时通讯汇总

Posted by jamie Blog on 2023-09-07 · 阅读 -- 次

1. 前言

之前写了一篇关于通过SSE实现服务端实时向客户端推送数据的文章，这是一种即时通信的方式，那么还有哪些方式可以在web端实现即时通讯呢？今天就来做一个汇总。

2. Ajax轮询

这种方式，就是很简单的，由客户端定时每隔一定时间请求服务端接口获取最新数据。不过它也有它的弊端，比如无法满足即时通信等富交互式应用的实时更新数据的要求。

这种浏览器端的小技术毕竟还是基于http协议，http协议要求的请求/响应的模式也是无法改变的，除非http协议本身有所改变。 不过它也不是没有优势啊，优势就是开发简单，后端接口不用做任何处理，由前端轮询调用即可。

3. comet

这是一种基于http长连接技术实现的一种技术，不过在我的工作经验中，基本没怎么见过他的影子。为啥呢？主要还是在很大一部分的浏览器对其不太支持。后来由于Ajax的推广，这种技术的实现就变得很不友好。

Comet的实现主要有两种方式，基于Ajax的长轮询（long-polling）方式和基于 Iframe 及 htmlfile 的流（http streaming）方式。

3.1 长轮询

服务器端接收到请求后，会阻塞请求直到有数据或者超时才返回，浏览器JS在处理请求返回信息（超时或有效数据）后再次发出请求，重新建立连接。在此期间服务器端可能已经有新的数据到达，服务器会选择把数据保存，直到重新建立连接，浏览器会把所有数据一次性取回。

3.2 基于 Iframe 及 htmlfile 的流

Iframe是html标记，这个标记的src属性会保持对指定服务器的长连接请求，服务器端则可以不停地返回数据，相对于第一种方式，这种方式跟传统的服务器推则更接近。

在第一种方式中，浏览器在收到数据后会直接调用JS回调函数，但是这种方式该如何响应数据呢？可以通过在返回数据中嵌入JS脚本的方式，如 <script type="text/javascript">js_func('data from server')</script>，服务器端将返回的数据作为回调函数的参数，浏览器在收到数据后就会执行这段JS脚本。

import org.springframework.context.annotation.Configuration;
import org.springframework.web.socket.config.annotation.EnableWebSocket;
import org.springframework.web.socket.config.annotation.WebSocketConfigurer;
import org.springframework.web.socket.config.annotation.WebSocketHandlerRegistry;

@Configuration
@EnableWebSocket
public class WebSocketConfig implements WebSocketConfigurer {

    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        registry.addHandler(new MyWebSocketHandler(), "/websocket")
                .addInterceptors(new HandshakeInterceptor());
    }
}

在上面的代码中，我们通过调用registry.addHandler()方法注册了一个WebSocket处理器，并指定了处理WebSocket连接的URL路径为/websocket，同时还添加了一个拦截器用于处理WebSocket握手请求。

import org.springframework.web.socket.TextMessage;
import org.springframework.web.socket.WebSocketHandler;
import org.springframework.web.socket.WebSocketSession;

public class MyWebSocketHandler implements WebSocketHandler {

    @Override
    public void afterConnectionEstablished(WebSocketSession session) throws Exception {
        // 在建立连接后执行的操作
        System.out.println("WebSocket连接已建立");
    }

    @Override
    public void handleMessage(WebSocketSession session, TextMessage message) throws Exception {
        // 处理接收到的消息
        System.out.println("接收到消息：" + message.getPayload());
        
        // 回复消息
        session.sendMessage(new TextMessage("已收到消息：" + message.getPayload()));
    }

    @Override
    public void handleTransportError(WebSocketSession session, Throwable exception) throws Exception {
        // 处理传输错误
        System.out.println("WebSocket传输错误：" + exception.getMessage());
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus closeStatus) throws Exception {
        // 在连接关闭后执行的操作
        System.out.println("WebSocket连接已关闭");
    }

    @Override
    public boolean supportsPartialMessages() {
        return false;
    }
}

在上面的代码中，我们重写了WebSocketHandler接口的几个方法，分别对应WebSocket连接建立、接收消息、传输错误和连接关闭时的操作。

最后启动项目，用postman可以直接访问websocket接口。例如示例的接口：ws://:/websocket

6. 总结

最后做一下总结，对四种技术的比较。

  • Ajax轮询

优点：简单易实现，适用于大部分浏览器，不需要特殊支持。
缺点：频繁发送请求会增加服务器负载和网络流量，延迟高，不适用于实时性要求较高的场景。

  • Comet

优点：相较于Ajax轮询，减少了请求的数量，能够更快地获得响应数据。
缺点：对服务器的资源占用较高，需要维护大量的长连接，容易造成资源浪费。

  • WebSocket

优点：实时性好，低延迟，服务器可以主动推送数据给客户端，节省网络流量和服务器资源。
缺点：需要浏览器和服务器的支持，不适用于不支持WebSocket协议的旧浏览器。

  • SSE（Server-Sent Events）

优点：相较于Comet，SSE协议定义更简单，易于使用。
缺点：不支持双向通信，只能由服务器向客户端单向推送，不适用于需要客户端向服务器发送数据的场景。

总结来说，Ajax轮询和Comet是传统的实现方式，对服务器资源消耗比较大，而WebSocket和SSE是HTML5新增的技术，具有实时性好、低延迟等优点。在选择实现技术时，需根据具体需求和环境来进行选择。如果需要双向通信且客户端支持WebSocket，推荐使用WebSocket；如果只需要服务器向客户端单向推送数据，可以考虑使用SSE。对于兼容性要求较高的场景，可以使用Ajax轮询或者Comet。
