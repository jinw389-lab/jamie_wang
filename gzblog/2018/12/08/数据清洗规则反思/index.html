数据清洗规则反思

Posted by jamie Blog on 2018-12-08 · 阅读 -- 次

1.背景

在做大数据相关产品项目中，我相信大多都会涉及到数据的一系列清洗问题。原始数据经过一系列清洗后，得到预期数据。下面有关涉及清洗项目开发的一些设计与思考。

2.场景

假如有多个清洗规则：

  1. 名单身份证15位转18位;
  2. 过滤字段;

数据经过上面两条清洗规则后得到预期数据。

3.实现方案

  1. if判断执行

 //执行身份证补全

 //过滤字段
}

    这样做有的优点是简单，若规则有限且是固定下来的，这样做也不可厚非，但是哪有不变更的需求啊，那岂不是就要接着if…..if啊。看着真的很头大啊！很显然这种方式就不可取啦。

  2. 运用策略模式

public class IdentityRule implements Rule {
    @Override
    public List<List<Object>> clear(List<List<Object>> data) {
        //身份证补全实现
        return null;
    }
}


public class FieldfilteringRule implements Rule {
    @Override
    public List<List<Object>> clear(List<List<Object>> data) {
        //字段抽取实现
        return null;
    }
}

public class Environment {
    private Rule rule;

    List<List<Object>> clear(List<List<Object>> data){
        return rule.clear(data);
    }
    public void setRule(Rule rule){
        this.rule = rule;
    }
}

public static void main(String[] args) {
        List<List<Object>> data = new ArrayList<>();
        Environment environment = new Environment();

        environment.setRule(new IdentityRule());
        data = environment.clear(data);
        
        environment.setRule(new FieldfilteringRule());
        data = environment.clear(data);
    }

这样的话要是有新的规则的话，只需要实现Rule接口即可。但是在实际开发中一条数据经过多次清洗，可以通过循环解决，具体的规则属性可以封装为组件，交由spring管理，并在数据库中进行维护。执行清洗的时候就可以这样做，伪代码实现

            environment.setRule(SpringContextUtils.getBean(name,Rule.class));
            data = environment.clear(data);
        }
